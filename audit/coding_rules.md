CODING TASK (literature audit, first coding). Code each paper on the 13-field sheet using ONLY its full text, provided as a local text file (path in your batch). Do not use the web. Read the abstract, data, method, evaluation and results sections carefully; search the text (grep) for key terms before deciding. Never guess: if the paper does not say, use the "No" or "Unclear" value the rules below give.

FIELDS (exact allowed values) AND DECISION RULES
1. Persistence benchmark (Yes/No/Unclear): Yes if results for a random-walk, naive or no-change forecast are reported. Unclear if such a benchmark is mentioned but no results for it are shown. Otherwise No.
2. Relative or returns metric (Yes/No/Unclear): Yes if accuracy is reported relative to persistence (Theil's U2, MASE, relative RMSE vs naive, skill score) OR the forecast target and evaluation are returns (log or simple returns). Directional accuracy alone does not count. Unclear only if the target unit cannot be determined.
3. Price R2 as headline (Yes/No): Yes if R2 computed on price levels is used to claim performance (in the abstract, conclusion, or as a main metric in the results text). No otherwise (including R2 only on returns, or R2 not reported).
4. Significance test (Yes/No): Yes if a formal test of forecast-accuracy differences is reported (Diebold-Mariano, HLN, Model Confidence Set, SPA/Reality Check, Giacomini-White, Wilcoxon or t-test on forecast errors, etc.). Tests of stationarity, normality or residuals do NOT count.
5. Robust variance (Yes/No/Not applicable): Not applicable if field 4 = No. Yes if the accuracy test allows for autocorrelated errors (Newey-West/HAC long-run variance, HLN small-sample correction of DM, bootstrap-based MCS/SPA). No if a plain DM or t-test without such a correction, or the paper does not say.
6. Multiple-testing control (Yes/No/Not applicable): Not applicable if field 4 = No, or only ONE accuracy test is run. Yes if a correction is applied (Holm, Bonferroni, FDR, MCS, SPA). No if several tests are run without correction.
7. Chronological split (Yes/No/Unclear): Yes if training data come strictly before test data (time-ordered split, rolling or walk-forward). No if random split, shuffling, or k-fold CV is used for the reported test results. Unclear if the paper does not say how the split is made.
8. Leakage control stated (Yes/No): Yes ONLY if the paper explicitly states a measure that keeps future information out of inputs (e.g. scaler/normaliser fitted on training data only; decomposition or features computed without future data; rolling one-step forecasts using only data up to the forecast origin; lagged features explicitly). Otherwise No.
9. Same horizon for all components (Yes/No/Unclear): Yes if the paper makes clear that the statistical and ML components produce forecasts for the same step (e.g. both one-step-ahead, rolling). No if a mismatch is evident (e.g. ARIMA forecasts the whole test period in one static multi-step run while the ML part is one-step). Unclear if not stated.
10. Unit consistency stated (Yes/No/Unclear): Yes if the paper states that all component forecasts are put in the same unit or scale (e.g. inverse-normalised, or all in returns) before combining and evaluating. No if mixed units are evident. Unclear if not stated.
11. Code public (Yes/No): Yes only if a working link to the code (GitHub, Zenodo, etc.) is given. "Available on request" = No.
12. Data public (Yes/No): Yes if the data source AND the exact period (start and end dates) are fully stated. Otherwise No.
13. Headline improvement: the largest improvement the ABSTRACT claims, as a percentage with one decimal (e.g. "35.2%"). If the abstract states a % directly, use it. If the abstract gives the hybrid's error and a baseline's error, compute the % reduction (1 - hybrid/baseline) x 100 and say "computed" in the source column. If the abstract gives no number allowing this, write "Not given".
14. Headline improvement source (quote location): where the number comes from, e.g. "Abstract, sentence 5 (MAPE vs ARIMA)" or "Abstract, computed from RMSE 2.1 vs 3.4". Keep under 15 words; do not quote more than 10 words.
15. Notes: at most 40 words: the key evidence behind the less obvious codes (fields 7-10 especially), e.g. "MinMax scaler fitted on full series before split".
